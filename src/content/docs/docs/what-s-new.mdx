## What's New in Material Theme UI v14.2.0

This release brings significant expansions to the **Language Additions** ecosystem, introducing **User-Defined Custom Additions**,
**Framework and Library Providers**, dedicated **HTML & CSS Additions**, as well as the new **UI Theme Inspector**.

### Custom Language Additions

You are no longer limited to pre-configured keywords. You can now define your own language additions to highlight specific functions,
identifiers, or variables directly in your code. By entering custom words or prefix patterns (such as `use*`) into the Language Additions
settings, they will automatically be exposed to the corresponding Color Scheme page.

<Figure content="/screens/additions/customEntries.png" caption="Custom Language Additions Settings" />

- Add custom identifiers per language in **Settings | Appearance & Behavior | Material Theme | Language Additions**.
- Supports comma-separated or newline-separated values.
- Supports trailing wildcards (e.g. `use*` will match `useState`, `useEffect`, `useCustomHook`).
- Customize colors under the `Custom` category in each language's **Color Scheme** additions page.

### Language Additions Providers

To enhance readability and provide immediate visual distinction for common frameworks and libraries, Material Theme UI now comes with
pre-packaged providers. In addition, an open extension point allows third-party plugin authors to contribute their own additions.

<div class="masonry">
<Figure content="/screens/additions/customProvidersJS.png" caption="Custom Providers - JavaScript" />
<Figure content="/screens/additions/customProvidersKotline.png" caption="Custom Providers - Kotlin" />
</div>

Built-in framework and library providers include:

- **React Hooks**: `useState`, `useEffect`, `useContext`, `useReducer`, `useMemo`, `useCallback`, etc.
- **Angular**: `@Component`, `@Injectable`, `@Directive`, `@Pipe`, `ngFor`, `ngIf`...
- **Vue**: `use*`, `watch*`, `computed`, `ref`, `reactive`...
- **NestJS**: `@Controller`, `@Injectable`, `@Module`, `@Get`, `@Post`...
- **Django**: `@login_required`, `@app.route`, `views.View`...
- **Spring**: `@Controller`, `@Service`, `@Repository`, `@Autowired`, `@Component`...
- **Laravel**: `@Route`, `@Controller`, `@Middleware`...
- **IntelliJ Platform SDK**: `@NotNull`, `@Nullable`, `Project`, `PsiFile`, `ApplicationManager`...
- **Rails**: `before_action`, `after_save`, `validate`, `has_many`, `belongs_to`...

### HTML & CSS Additions

Granular syntax highlighting is now extended to HTML Pages and CSS stylesheets. You can customize colors for HTML tags (semantic,
structural, layout, forms, media) and attributes (classes, IDs, ARIA, data attributes, boolean flags), as well as CSS properties,
pseudo-classes, functions, and at-rules.

<div class="masonry">
<Figure content="/screens/additions/htmlAdditions.png" caption="HTML Additions Color Scheme" />
<Figure content="/screens/additions/cssAdditions.png" caption="CSS Additions Color Scheme" />
</div>

:::caution
**Note**: Language Additions is a **Premium** feature.
:::

### UI Theme Inspector

A new **Theme Inspector** is now available in the **Theme Color Overrides** tool window. It allows you to inspect any UI element in the IDE
on click to discover its theme property keys, color scheme keys, and active color values.

<Figure content="/screens/override/inspector2.png" caption="Theme Inspector" />

## What's New in Material Theme UI v14.0.0

This upcoming version introduces the **File Header**, improved **Wizard** steps, a new **Tool Window Stripes Handle**, the **Theme Colors
Override** tool window,
and a **Second Gradient Anchor** in the **Window Coloring** settings.

### File Header

A configurable header can now be displayed at the top of every open editor, completing the **Project Banner** already available. Similarly
to the Project Banner,
the *File Header* can provide useful information about the current file, such as its name, path, module, and more.

<Figure content="/screens/fileHeader/fileHeader.png" caption="File Header" />

- Configure it globally in the app settings, or override it per project.
- Choose between three styles: *Island*, *Seamless* and *Header*.
- Give each header a generated tint to better distinguish between files.
- Customize the position, text alignment, dimensions, opacity, font and colors.
- Provides a few handy actions, such as *Copy Path* or *Open in Split*.
- You can also change the current pattern by right-clicking and selecting from a list of predefined patterns.

<Figure content="/screens/fileHeader/customPresets.png" caption="Predefined Patterns" />

In addition, both the **Project Banner** and the **File Header** can now style the displayed information, e.g. change the color, make the
text bold, italic, etc.

This allows you to highlight important information, such as the file name, and make it stand out from the rest of the text.

<Figure content="/screens/fileHeader/headerStyle.png" caption="Header Style" />

:::caution
**Note**: This feature is available for **Premium** and **Project Frame** license owners.
:::

### Wizard

The theme setup wizard has been improved with new steps and a better layout. Two new wizard steps allow you to configure the
**Banner/Header**
and **Regions/Peek** settings directly during initial setup, making it easier to personalize your workspace from the start.

The wizard UI has also been refined with improved layout using WrapLayout and minimum size constraints, ensuring a more consistent and
comfortable experience across different window sizes.

<div class="masonry">
<Figure content="/screens/wizard/welcomeStep.png" caption="Wizard Welcome Step" />
<Figure content="/screens/wizard/themesStep.png" caption="Wizard Themes Step" />
<Figure content="/screens/wizard/accentStep.png" caption="Wizard Accent Step" />
<Figure content="/screens/wizard/contrastStep.png" caption="Wizard Contrast Step" />
</div>

### Tool Window Stripes Handle

A new feature is available inside the **Features** settings: the **Tool Window Stripes Handle**. This feature allows you to automatically
hide the tool window stripes, and reveal them when you hover over a small handle on the side of the IDE.

This can be particularly useful for **"Zen Users"**, i.e. people who usually hide their tool windows to focus on the code.

<Figure content="/screens/features/autohide.gif" caption="Auto-hide Tool Window Stripes" />

You can configure the auto-hide behavior, the hover delay, and the handle width.

:::caution
**Note**: This feature is available for all users.
:::

### Second Gradient Anchor

The **Window Coloring** settings now allow you to configure a second anchor for the gradient fill.

<Figure content="/screens/windows/doubleGradient.png" caption="Double Gradient" />

### Theme Colors Override Tool Window

Previously, you could preview the colors of the current theme, but you couldn't edit them. That's now possible with the new **Theme Colors
Override** tool window, which allows you to edit the colors of any theme in-place.

<Figure content="/screens/override/toolWindow.png" caption="Override Theme Colors" />

This Tool Window gives you a preview of the current theme's colors, and allows you to edit them in-place. Upon clicking on a color, you will
be presented with a custom color picker that allows you to pick a color from the current theme's colors, or pick a new one.

<Figure content="/screens/override/colorSelector.png" caption="Color Selector" />

You can also filter out properties, reset to their default values, or add/remove custom properties if they are not present in the current
theme.

:::caution
**Note**: This is the same feature as the one described in the v13.1.0 release notes, but in this version it is available as a Tool Window
in addition of the Settings page. As such, it is also only available for **Premium** and **Custom Theme** license owners.
:::

## What's New in Material Theme UI v13.1.0

The new version focuses on bringing new themes to the table, as well as improving the existing ones.
It also introduces a new feature to edit the theme colors in-place, allowing for a more personalized experience.

Hope you like it!

### New Themes

This version introduces three new themes to the collection:

- **Winter Is Coming**: A dark theme with a cold, icy color palette.
- **Shades of Purple**: A vibrant theme with a purple color scheme.
- **Noctis**: A dark theme with a deep, rich color palette.

<div class="masonry">
<Figure content="/screens/themes/noctisSmall.png" caption="Noctis" />
<Figure content="/screens/themes/winterSmall.png" caption="Winter Is Coming" />
<Figure content="/screens/themes/shadesSmall.png" caption="Shades of Purple" />
</div>

In addition, the **Omni** and **Cobalt2** color schemes have been reworked from the ground up to better look like their
VSCode counterparts, while also improving their overall color schemes and aesthetics.

### Override Theme Colors

The other highlight of this version is the repurposing of the **Preview Theme Colors** page into a full-fledged **Theme
Colors Override** settings page allowing you to customize any theme's colors.

<Figure content="/screens/override/overrideThemeColors.png" caption="Override Theme Colors" />

:::caution
**Note**: This feature is only available for **Premium** and **Custom Theme** license owners.
:::

Inside this page you can:

- Filter out properties by name or color.
- Override a theme color that will be persisted for that specific theme.
- Reset a property or all properties to their defaults.
- Import and export your theme color overrides to share with others.

<Figure content="/screens/override/editColor.png" caption="Edit Color" />

:::caution
**Note**: Any properties listed in the *Theme Ignores* will be ignored, no matter what color you give it.
:::

## What's New in Material Theme UI v13.0.0

Even though version 12 was deployed not long ago, this new version brings a lot of new features and refactorings, which
is a pretty big change.

Between **Color Scheme Overrides**, **Peek**, **Window Coloring**, **Stylish Regions** and other new settings, this
version changes the underlying architecture of the **Actions System**, **Analytics**, **Accent Colors**, **Project
Banner**, just to name a few.

### Stylish Regions

Folded regions can now become visual landmarks instead of plain folded blocks. **Stylish Regions** redesigns the
appearance of folded regions, making them more visually distinct and easier to identify.

You can choose from a variety of styles to suit your preferences, including:

- **Wavy**: A soft, undulating separator, reminiscent of what you can already experience in diff windows.
- **Line**: A clean horizontal rule that keeps boundaries subtle and precise.
- **Stripe**: A bold, high-contrast separator that makes regions easy to spot while scrolling.

<div class="masonry">
<Figure content="/screens/regions/wavy.png" caption="Wavy Separator" />
<Figure content="/screens/regions/line.png" caption="Line Separator" />
<Figure content="/screens/regions/stripe.png" caption="Stripe Separator" />
</div>

The **Advanced** plan unlocks deeper customization, including custom separator and title colors, font family and size,
and title block positioning. You can also generate a background color automatically from the region description. This
gives regions with the same name a
consistent color across files, making familiar groups such as *Constants*, *Helpers*, or *API Calls* instantly
recognizable.

You can configure these options in `Settings → Appearance → Material Theme UI → Regions`. The basic enable/disable
option remains free for everyone, so you can try the default Wavy style before enabling the full set of customization
options.

----

### Window Coloring and Gradients

The former **Project Banner** window-coloring options are now available in their own settings page. **Window Coloring**
applies a distinctive color to the IDE frame for each project, making it much easier to identify the right window when
several projects are open. Colors can be generated consistently from a project name, overridden manually, or regenerated
when you want a different visual identity.

Alongside the existing **Solid Fill**, version 13.0.0 introduces **Gradient Fill** for a more polished transition
between the project color and the theme's panel color:

- **Linear** gradients transition along a configurable angle, allowing horizontal, vertical, or diagonal color flows.
- **Radial** gradients radiate from a configurable anchor point. You can place the anchor at any of nine positions, from
  top-left to bottom-right, to create anything from a corner glow to a centered spotlight.
- **Gradient size and opacity** let you control how strongly the project color appears and how quickly it fades into the
  surrounding frame.

<div class="masonry">
<Figure content="/screens/windows/gradient1.png" caption="Window Coloring" />
<Figure content="/screens/windows/gradient2.png" caption="Gradient Fill" />
</div>

Window Coloring can be configured globally at `Settings → Appearance → Material Theme UI → Window Coloring`. You can
also enable **Regenerate window color on theme change** to automatically pick a new color whenever you switch themes.

For more granular control, **Per-Project Settings** allows you to choose different frame regions, fill modes, gradient
settings, and colors for each project. This makes it possible to give each project its own customizations, making them
distinct from one another.

### Peek Evolution

Peek has received a number of improvements to make it more useful and easier to use:

- You can now use **Replace Ctrl-click** to replace the default `Ctrl+Click/Cmd+Click` behavior with the *Inline Peek*
  feature, keeping you in context while exploring definitions.
- To improve the reading experience, the Peek panel now **defaults to full width**.
- We've added **F4 navigation** for faster jumping between results
- Implemented a **ServiceDimensionKey** to ensure consistent popup sizing when switching between peek panels.
- Furthermore, interacting with the Peek window no longer triggers parent container scrolling, providing a more stable
  and focused editing experience.

:::caution
**Note**: The **Replace Ctrl-click** option is a destructive action that modifies your current keymap. Please make a
backup before enabling it.
:::

### New Color Scheme Overrides

We’ve expanded the **Color Scheme Overrides** to give you finer control over your workspace's aesthetics. You can now
override the colors for **Search Results**, the **Identifier Under Caret**, and **Matched Braces** using the **Accent
Color**. This ensures key UI elements are always consistent with your chosen theme and accent, regardless of the
underlying color scheme's default colors.

<Figure content="/screens/colorSchemes/overrideAccents.png" caption="Override Accents" />

We've also fixed the issue with **Diff Colors Opacity** not persisting after restarts.

### Outline Notifications

Experience a cleaner, more modern approach to IDE notifications with **Outline Notifications**. These notifications
feature a subtle, **accent-colored outline** styling that integrates seamlessly with the rest of the Material Theme UI,
reducing visual clutter while ensuring key information remains prominent.

<Figure content="/screens/ui/notificationsOpaque.png" caption="Outline Notifications" />

### Random Accent Color

The **Accent Color Picker** and **Accent Color Settings** now feature a **Random Accent Color** option.

This allows you to generate a new accent color outside the predefined swatches, giving you a fresh and unique look for
your IDE.

<Figure content="/screens/accents/accentPicker.png" caption="Material Accent Picker" />

### Architectural Improvements

Behind the scenes, version 13.0.0 includes a massive architectural refactor to ensure the plugin remains fast and
maintainable as it grows:

- **Dynamic Action System**: The entire action system has been rewritten to be fully dynamic, reducing boilerplate code.
  This allows for easier addition of new actions and features, while also improving startup performance.
- **Modular ThemeManager**: The core `ThemeManager` has been broken down into smaller, specialized services grouped by
  module. This makes the code more maintainable and testable, and less prone to bugs.
- **Boilerplate Reduction**: We've significantly reduced the boilerplate code required for Configurables and States,
  leading to a more reliable settings experience and faster delivery of new features.
- **Analytics Overhaul**: We've also improved the Analytics Collection, making it more efficient to follow user
  interactions and feature usage, which will help us prioritize future improvements.

These changes might not be immediately visible, but they provide a more stable foundation for the future of Material
Theme UI.
